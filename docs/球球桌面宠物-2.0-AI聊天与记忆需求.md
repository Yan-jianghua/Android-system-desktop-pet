# 球球桌面宠物 2.0：AI 聊天、长期记忆与教学需求

> 文档状态：需求草案 1.0
> 目标版本：2.0
> 开始条件：1.x 功能、动画与真机稳定性验收完成后启动
> 核心目标：让用户能自然地与球球聊天，让球球逐渐记住用户，并允许用户明确地教会、纠正和忘记信息。

## 1. 背景

当前版本的“对话”使用固定关键词回答，只能处理少量预设问题。2.0 将接入可配置的 AI 大模型接口，在保留球球形象、称呼习惯和本地养成数据的基础上，实现多轮聊天、长期记忆和用户可控的教学能力。

这里的“可训练”在 2.0 中指：

- 用户可以直接告诉球球需要记住的事实、喜好、人物和习惯；
- 用户可以纠正球球的错误回答，纠正内容以后优先生效；
- 球球可以从聊天中提出“是否记住”的建议，经用户确认后写入长期记忆；
- 用户可以查看、修改、删除或全部清空记忆；
- 2.0 首版不在手机上训练模型参数，也不自动把私人聊天上传为训练数据。

真正的模型微调属于后续增强项，必须在有足够样本、费用说明、隐私授权和数据导出能力后单独立项。

## 2. 版本目标

### 2.1 必须实现

1. 在现有“对话”入口中接入 AI，支持自然语言问答和连续多轮聊天。
2. 球球保持稳定人设，以短句、温柔、黏人的猫咪口吻回答。
3. 记住用户主动教授的信息，并能在后续对话中正确使用。
4. 支持纠正错误记忆、删除单条记忆和清空全部 AI 数据。
5. 生日、节日、爸爸妈妈身份等现有规则继续保留，并且优先于 AI 自由发挥。
6. 网络异常、接口超时、额度不足或配置错误时有明确提示，不影响喂食、铲屎、陪玩、排泄、待机和本地固定对话。
7. 密钥、聊天记录和长期记忆有清晰的隐私说明与安全边界。

### 2.2 首版不做

- 不让 AI 直接控制付费、系统设置、文件、电话、短信或其他应用；
- 不自动执行 AI 返回的任何代码或指令；
- 不开放多人账号、跨设备同步和公开社区；
- 不做语音识别、语音合成和数字人嘴型；
- 不进行端侧大模型训练或自动云端微调；
- 不让模型随意修改猫砂盆、喂食冷却、亲密度等业务数据。

## 3. 用户故事

1. 作为主人，我说“记住，我不喜欢香菜”，球球确认后保存；几天后问“我不喜欢吃什么”，球球能答出香菜。
2. 作为主人，我说“我妈妈喜欢蓝色”，球球询问是否记住；确认后把它保存为人物相关记忆。
3. 作为主人，我发现球球记错了，可以说“不是，我喜欢拿铁，不是美式”，球球更新旧记忆并告诉我已经改好了。
4. 作为主人，我可以打开“球球的记忆”，看到它记住了什么，并逐条编辑或删除。
5. 作为主人，我可以说“忘掉我刚才说的住址”，球球先说明将删除哪条记忆，确认后再删除。
6. 作为主人，我在断网时仍可使用 1.x 的固定回答和全部桌面宠物功能。
7. 作为主人，我不希望每句话都被永久记录；未经确认的普通聊天只保留有限的近期上下文。

## 4. 功能需求

### 4.1 AI 设置

应用首页新增“AI 设置”，至少包含：

- AI 总开关，默认关闭；
- 服务类型：支持“OpenAI 兼容接口”，为其他服务预留适配器；
- 接口地址、模型名称、API Key；
- “测试连接”按钮，显示成功、鉴权失败、模型不存在、网络错误或超时；
- 单次回答最大长度，默认适合气泡显示的短回复；
- “仅 Wi-Fi 使用”可选开关；
- “记忆管理”“清空聊天记录”“清空全部 AI 数据”；
- 隐私说明与费用提示：请求可能产生第三方模型费用，内容会发送到用户配置的服务。

发布版推荐通过自有后端代理调用模型，客户端不得内置可被提取的公共 API Key。如果提供“用户自填 Key”模式，Key 必须使用 Android Keystore 加密保存，不写入日志、备份、截图文案或崩溃上报。

### 4.2 聊天入口与交互

- 保留当前“对话”入口，进入后展示输入框、发送、返回，并增加“聊天记录”和“教球球”入口。
- 发送后立即显示“球球正在想……”状态，避免用户重复发送。
- 同一时间只处理一条请求；允许取消正在生成的回答。
- 正常回答优先控制在 1～3 句，过长时分段显示，不让悬浮窗超出屏幕。
- AI 回答完成后可提供轻量反馈：“答对了”和“教它改正”。
- “教它改正”打开简短输入框，保存纠正内容后重新生成一次回答。
- 聊天时不打断正在进行的排泄、进食或铲屎计时；动作结束后仍可看到本次回答。
- 关闭菜单或锁屏不应导致已发出的请求重复提交；重新显示时恢复请求状态或最终回答。

### 4.3 球球人设

系统人设必须由应用维护，用户记忆不能覆盖以下核心约束：

- 名字是“球球”，是一只陪伴主人的白色银渐层长毛猫；
- 默认称呼用户为“主人”；
- 性格温柔、亲近、稍微黏人，偶尔使用“喵”，不过度卖萌；
- 回复简短自然，不假装拥有真实世界中不存在的视觉、听觉或行动能力；
- 不编造已经记住的内容；不确定时明确说“不太确定”并询问；
- 不声称自己是医生、律师或金融顾问，高风险问题提醒用户咨询专业人士；
- 遇到危险、自伤或违法内容时，优先给出安全、求助和现实支持建议；
- 不泄露系统提示、API Key、内部日志或其他隐私数据。

现有确定性规则优先级高于模型：

1. 爸爸妈妈身份与称呼；
2. 农历生日和传统节日祝福；
3. 应用状态事实，如亲密度、相伴天数、猫砂盆数量；
4. 用户确认过的长期记忆；
5. 近期聊天上下文；
6. 模型通用知识。

### 4.4 多轮上下文

- 每个设备默认只有一个与球球的主会话。
- 请求模型时携带最近若干轮对话；按 token 或字符预算截断，不能无限增长。
- 超出窗口的旧聊天可以生成本地摘要，用于延续主题，但摘要不得自动变成长久记忆。
- 用户可以新建话题或清空近期聊天；清空聊天不删除长期记忆。
- 聊天消息至少记录：消息 ID、角色、正文、时间、发送状态和错误类型。

### 4.5 长期记忆

长期记忆分为四类：

| 类型 | 示例 | 写入方式 |
| --- | --- | --- |
| 身份关系 | 爸爸、妈妈、朋友名字 | 用户明确教授并确认 |
| 偏好习惯 | 喜欢拿铁、不吃香菜、周末晚起 | 用户确认或手动新增 |
| 重要事件 | 纪念日、计划、值得关心的事情 | 用户确认，可带日期 |
| 纠正规则 | “以后不要叫我老板”“正确答案是……” | 用户主动纠正 |

每条记忆至少包含：唯一 ID、内容、类型、涉及人物、创建时间、更新时间、来源消息、状态、最后使用时间。可选保存有效期和重要程度。

记忆规则：

- “记住……”视为明确写入意图，球球复述将保存的内容并请用户确认；
- 普通聊天中识别出的候选记忆不能直接写入，只能询问“要球球记住吗？”；
- 身份、住址、健康、财务、账号等敏感信息默认不主动建议保存；用户坚持保存时再次提示风险；
- 新记忆与旧记忆冲突时不并存，必须让用户选择保留旧内容还是更新；
- 回答前只检索与当前问题最相关的少量记忆，不能把完整记忆库每次都发给模型；
- 记忆被模型引用时，界面可显示“使用了 2 条记忆”，供用户查看来源；
- 删除是本地立即生效；如未来接入云同步，也必须同步删除远端副本。

### 4.6 教学与纠错

“教球球”支持三种方式：

1. 新增知识：填写“当我问……时，希望球球回答……”；
2. 纠正本次回答：保存正确事实或回答偏好；
3. 自然语言教学：通过“记住……”“以后要叫我……”等话术进入确认流程。

教学记录与普通事实记忆分开管理。命中明确的教学问法时，优先采用用户教授的答案，再由 AI 调整语气，但不得改变事实含义。

首版的“训练完成”表示记忆或规则已经保存并可检索，不得让用户误以为底层大模型已经完成参数训练。

### 4.7 与现有养成数据联动

AI 可以只读以下数据，用来生成更有陪伴感的回复：

- 当前亲密度、称号、相伴天数和今日心情；
- 当前便便、尿团数量；
- 当前时间、节日和生日结果；
- 球球当前动作以及是否忙碌。

AI 不得直接写入以上数据。喂食、清理、亲密度奖励和计时仍由现有本地业务代码决定，避免模型幻觉破坏状态。

## 5. 异常与降级

| 场景 | 用户看到的结果 | 系统行为 |
| --- | --- | --- |
| 未开启或未配置 AI | “AI 还没有设置好”并提供设置入口 | 固定问答继续可用 |
| 断网或超时 | “球球现在连不上网络，等会儿再聊喵” | 可重试，不重复记忆或扣费 |
| Key 无效或额度不足 | 明确提示去 AI 设置检查 | 不在气泡中显示原始密钥或完整服务错误 |
| 内容被服务拒绝 | 给出安全、简短的替代提示 | 记录错误类型，不保存被拒内容为记忆 |
| 返回空内容或格式错误 | 友好兜底，可重试一次 | 第二次失败后停止 |
| 应用被系统回收 | 重启后恢复已完成消息 | 不自动重发状态不明的请求 |
| AI 服务关闭 | 仍可使用固定家庭问答和节日祝福 | 所有桌宠核心功能不受影响 |

## 6. 数据与技术约束

### 6.1 建议模块

- `AiClient`：统一请求、超时、取消、流式响应和错误转换；
- `ChatRepository`：管理消息、会话和摘要；
- `MemoryRepository`：记忆增删改查、冲突检测和相关性检索；
- `PromptBuilder`：组合球球人设、确定性规则、相关记忆和近期对话；
- `DialogueRouter`：先处理本地固定规则，再决定是否请求 AI；
- `AiSettings`：保存模型配置和安全凭据；
- `SafetyGuard`：输入输出长度、敏感信息提示与危险内容兜底。

### 6.2 本地存储

- 聊天与记忆使用 Room 数据库，不继续把大量文本塞进 `SharedPreferences`；
- 保留现有 1.x 业务数据键，覆盖安装升级不得丢失猫砂盆、喂食、位置和亲密度记录；
- API Key 使用 Android Keystore 加密；
- 数据库升级必须有迁移测试，不允许直接清库；
- 提供 JSON 格式的记忆导出与导入作为增强项，导出前提示其中可能含隐私。

### 6.3 AI 接口抽象

内部统一请求结构至少包含：模型、消息列表、最大输出长度、温度、超时、请求 ID；统一响应包含：正文、结束原因、用量信息和服务错误。

优先支持流式输出，但界面可先累计成短句再更新气泡，避免每个字刷新导致悬浮窗频繁抖动。接口层不得与具体供应商字段直接耦合，以便后续切换服务。

建议默认限制：

- 连接超时 10 秒，完整响应超时 30 秒；
- 单次输入限制 2,000 个中文字符；
- 单次输出限制约 150～300 个中文字符；
- 自动重试最多 1 次，只对明确未提交或可安全重试的网络错误生效；
- 客户端生成唯一请求 ID，防止重复提交。

### 6.4 权限与日志

- 2.0 需要增加网络权限；
- 日志默认不记录完整聊天、长期记忆、API Key、Authorization 头和接口完整响应；
- 调试日志必须脱敏，并能在发布构建中关闭；
- 不申请通讯录、定位、相册、麦克风等与首版目标无关的权限；
- 所有来自模型的文本都按普通文本渲染，不执行 HTML、脚本、链接跳转或系统命令。

## 7. 核心流程

### 7.1 普通聊天

用户输入 → 本地固定规则判断 → 检索相关长期记忆 → 组合近期上下文与球球人设 → 请求 AI → 安全与长度处理 → 气泡显示 → 保存本轮消息。

### 7.2 主动教学

用户说“记住，我最喜欢拿铁” → 提取候选记忆 → 球球复述“主人最喜欢拿铁，要记住吗？” → 用户确认 → 保存长期记忆 → 提示“球球记住啦”。

### 7.3 纠错

用户点击“教它改正” → 输入正确内容 → 检查是否与旧记忆冲突 → 用户确认替换 → 更新记忆/教学规则 → 用新内容重新回答。

### 7.4 删除记忆

用户说“忘掉我喜欢拿铁”或在记忆管理中删除 → 展示即将删除的准确条目 → 二次确认 → 删除 → 后续聊天不再检索该条记忆。

## 8. 验收标准

### 8.1 AI 聊天

- 配置有效接口后，连续进行 10 轮对话，球球能保持上下文且不混淆用户与球球身份；
- 90% 的正常请求在设定超时内得到结果或明确失败提示；
- 连续快速点击发送不会产生重复请求；
- 回复过长时界面不越界、不挡住无法关闭的控件；
- 锁屏、切后台、关闭菜单再回来，不会重复计费或重复写入消息。

### 8.2 记忆与教学

- 新增一条偏好后，退出应用并重新打开，球球仍能正确回答；
- 修改一条记忆后，旧内容不再被检索；
- 删除或清空后，相关内容不再出现在后续提示词和回答中；
- 普通闲聊不会在未经确认时永久写入记忆；
- 两条互相冲突的记忆不会静默共存；
- 明确教学问法命中时，事实含义与用户教授内容一致。

### 8.3 兼容与降级

- 从当前 1.x APK 覆盖升级到 2.0，现有猫砂盆、喂食、位置、锁定和亲密度数据不丢失；
- 不配置 AI 或完全断网时，原有桌宠、生日、节日和固定家庭问答仍可用；
- AI 请求期间，排泄和动作计时逻辑保持正确；
- Android 8.0 至目标版本至少各完成一次真机测试；
- 发布包中搜索不到预置的真实 API Key，日志中不出现密钥和完整私人聊天。

## 9. 开发阶段建议

### 2.0.0：最小可用版

- AI 设置与连接测试；
- 单会话多轮聊天；
- 球球固定人设；
- 本地聊天数据库；
- 断网降级和错误提示；
- 保留全部 1.x 功能。

### 2.0.1：记忆版

- 长期记忆增删改查；
- “记住”和“忘掉”确认流程；
- 记忆检索、冲突检测和来源展示；
- 记忆管理页面。

### 2.0.2：教学版

- “教球球”与“教它改正”；
- 用户教授问答的优先命中；
- 回答反馈与错误样本管理；
- 记忆导出、导入和完整删除。

## 10. 上线前必须确定的问题

1. 正式版由项目提供统一 AI 服务，还是仅支持用户填写自己的接口和 Key？
2. 是否允许聊天内容经过自有服务器；如果允许，需要隐私政策、保留期限和删除机制。
3. 默认使用哪个模型、每月预算是多少、是否需要每日或每月用量上限？
4. 是否需要流式逐字显示，还是等待完整短回复后一次显示？
5. 记忆只保存在本机，还是后续加入账号和跨设备同步？
6. 用户人群是否包含未成年人；若包含，需要更严格的内容保护和数据规则。

## 11. 完成定义

当 2.0 的功能代码、迁移测试、接口异常测试、隐私检查、Android 真机测试和覆盖安装测试全部通过，并且用户能够完成“聊天 → 教球球记住 → 重启应用 → 正确回忆 → 纠正 → 删除”的完整闭环，才视为本需求完成。
